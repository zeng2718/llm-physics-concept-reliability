# Constrained option-permutation protocol — test-secure summary

The constrained option-permutation plan was finalized before any variant was administered to a target model. This summary excludes actual answer letters, option meanings, option-level mappings, and stimulus transformations.

## Purpose and priorities

Option handling aimed to reduce direct carry-over of memorized source-item answer letters without compromising item validity. Priorities were fixed in this order:

1. G1–G5 validity gates (hard constraints);
2. Semantic dependencies and natural layout of options (hard constraints);
3. Variant correct letter differing from the source item (soft constraint);
4. Reasonable spread of answer positions across the sample (soft constraint).

## Registered outcome

Twenty-one of the 25 variants changed the correct answer letter. Four retained the source letter to preserve a natural numerical or spatial ordering. The per-variant changed/retained flag needed to reproduce the manuscript's sensitivity analysis is provided in `option_permutation_outcomes.csv`; the letters themselves are not provided.
